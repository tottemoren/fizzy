# 4. 命名・コメント

## 方針
- コメントは **かなり少ない**。コードを読めばわかることは書かない
- その代わり、**メソッド名がそのまま説明になる** ように命名する
- コメントを書くのは「**なぜそうしたか**」「**触る人が気をつけること**」に限られる

## 命名の例

| メソッド | 意味がそのまま読める |
|---------|-------------------|
| `card.close` / `card.reopen` | 閉じる／再オープン |
| `card.gild` / `card.ungild` | 金色にする／外す |
| `card.triage_into(column)` | 列に振り分ける |
| `card.awaiting_triage?` | 振り分け待ちか |
| `notify_recipients_later` | 受信者への通知を後で（非同期で）行う |

## コメントがある箇所の例

### 「なぜ」を説明するコメント
[app/models/notifier.rb](../../app/models/notifier.rb)

並行して動くジョブ同士の競合（race condition）を防ぐために、あえて値を毎回更新している理由を説明している。
**コードだけでは絶対に読み取れない意図** なのでコメントにしている。

### 将来の変更者への警告
[app/models/storage.rb](../../app/models/storage.rb)

「IMPORTANT: 新しいモデルに添付ファイルを追加したら、この定数も更新すること」という注意書き。
更新を忘れるとバリデーションが効かなくなる、という **見落としやすい依存関係** を明示している。

## STYLE.md の独特なルール

[STYLE.md](../../STYLE.md) には一般的な Rails の書き方と異なるルールがある。

| ルール | 内容 |
|-------|------|
| 条件分岐 | ガード節（早期 `return`）より `if / else` を好む |
| メソッドの並び | 呼び出される順に上から並べる |
| `private` の書き方 | `private` の下はインデントする |
| `!` の付け方 | `!` なしの対になるメソッドがあるときだけ付ける（破壊的だから付ける、ではない） |
